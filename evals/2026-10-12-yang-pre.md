## Review

False positives (flagged, label `N`), read statically:

- nb_65 — encoder fit on full data before `train_test_split`. Mechanically true; Yang label `N` (one-hot of a categorical column, no value statistics). Label policy disagreement.
- nb_1959 — `OrdinalEncoder.fit_transform` on the full frame, then split. Same as nb_65: label policy disagreement.
- nb_1162 — `LabelEncoder.fit_transform` on whole columns. Labeled `N` for overlap, not for absence of the pattern. Label policy disagreement.
- nb_2770 — `LabelEncoder.fit_transform` on whole columns before modelling. Labeled `N` for overlap. Label policy disagreement.
- nb_3594 — `StandardScaler.fit_transform(x)` on all rows, then `train_test_split(x_scaled, ...)`. Genuine leakage; the `[human errors]` tag suggests the label is wrong, so likely a correct flag.

False negatives (label `Y`, not flagged), read statically:

- nb_1743 — test frame imputed with its own mean via `fillna`; no fit/transform call for the detector to follow.
- nb_3065 — Keras `Tokenizer.fit_on_texts` on all headings before `KFold`; Tokenizer is not in the fitted-transformer set.
- nb_195 — not analysed: file exceeds the 20 MB input cap (exit 3). Source shows `scaler.fit` on the full frame before the split, so a miss from a larger-than-cap file, not from the detector.
- nb_2760 — z-score written by hand with `desc_mols.mean()` and `.std()` before the split; no scikit-learn object.
- nb_318 — median `fillna` inside a feature function applied to the full data before the split; not a fit call.
- nb_678 — Keras `Tokenizer.fit_on_texts` on the full dataset before the train/test split; same gap as nb_3065.
- nb_89 — `poly.fit_transform` re-applied to test arrays; a refit-on-test pattern, not fit-before-split.
- nb_2528 — `MinMaxScaler.fit_transform` on the full series, then the train/test boundary taken by slicing; no split call to anchor on.
- nb_296 — hand-written min-max normalisation over the full frame before `train_test_split`; no scikit-learn object.
- nb_3144 — `LabelEncoder.fit` on train and test values concatenated; train and test are already separate frames, so there is no split call.
- nb_1417 — `StandardScaler` and `PCA` fit on the full data, then train/test by index slicing; no split call.
- nb_1633 — `scaler.fit_transform` called on test data inside a helper; refit-on-test behind a function boundary.

Also: nb_334 (label `N`) is not valid JSON and exited 3; it counts as a true negative here.

Summary: 4 of 5 false positives are encoder-fit-before-split where Yang labels `N`; 11 of 12 misses are patterns the detector does not model (hand-written scaling, Keras Tokenizer, fillna statistics, slice splits, refit on test), and one is the size cap.

## Caveats

Yang labels are the paper authors' manual labels, not re-adjudicated here.
scicode-lint's ml-009/ml-010 were tuned to Yang definitions; Waldean's detectors were never run on this set before this file.
Only `pre` is comparable; Waldean has no class for `overlap` or `multi`.
The 34 notebooks without a `pre` label have Yang's `model` label `N`, some with a note such as `unsupervised` or `no test`. None was flagged, so precision and recall are the same with or without them; TN is 42 if they are excluded.
